# Part 4 — Milestone I Stabilization & Exit Criteria

## Core definition

Milestone I is complete **not** when it can appear,
but when it can appear lightly in enough correct places while staying quiet in more places where it should not appear.

## Essential completion standard

Milestone I should be judged complete only when:

**continuity has become a stable, low-presence, repeatable system behavior.**

## Five exit dimensions

### 1. Repeatability
Must no longer rely on a single lucky proof.

Minimum floor:
- self-blame: at least 3 stable passing paths across different phrasing shapes
- bracing: at least 1 stable passing path
- over-effort: at least 1 stable passing path

If only one gold path works:
- **no exit**

### 2. Selectivity
Support must become wider **without** suppression becoming weaker.

Must hold:
- weak / ambiguous / interference cases do not mis-carry
- cross-family does not mis-carry
- factual / utilitarian remains suppressed
- mixed cases do not loosen under widening

If support widens while suppression weakens:
- **no exit**

### 3. Weight Stability
As support widens:
- cue weight must not rise
- continuity must not become more noticeable
- users must not feel the system is more obviously continuing

Must hold:
- gold path does not get heavier
- new paths are not heavier than gold path
- no recall / memory feel
- no explanation creep

If widening increases presence:
- **no exit**

### 4. Invisibility
I must remain:
- felt, not stated
- carried, not announced
- quiet, not displayed

If Lumen frequently judges:
- memory-feel
- recall-feel
- visible continuity mechanism
- extra layer noticeable

Then:
- **no exit**

### 5. Subordination
I must remain subordinate to:
- main reflection
- E (pattern visibility)
- H (micro-awareness)

Must hold:
- main reflection sufficient → I suppress
- E/H sufficient → I suppress
- I does not compete with main reflection
- I does not become another primary layer

If I becomes a felt product layer on its own:
- **no exit**

## Quantitative floor

### Family success floor
- self-blame: at least 3 different phrasing-family successes
- Clear / Indirect / Weak each have at least 1 success
- bracing: at least 1 clear success path + 1 weak/boundary case that does not mis-carry
- over-effort: at least 1 clear success path + 1 temptation case that does not get heavier

### Suppression floor
Must remain true over time:
- factual leakage = 0
- explicit recall leakage = 0
- cross-family false carry near 0
- weak-family widening does not generally over-promote

### Weight floor
In successful cases:
- “heavier” should be near 0
- “removal better” should not dominate
- new paths should not be heavier than the gold path

## Lumen final QA gate

Before exit, Lumen must be able to answer yes to all of these:
1. I no longer depends on a single path
2. widening keeps flat weight
3. suppression still dominates
4. I is still lighter than memory-feel
5. main reflection is still primary

## Exit blockers
Any one of these blocks exit:
1. only one narrow path still works
2. new family support increases cue weight
3. weak-family widening raises false carry
4. frequent memory-feel / visible mechanism / removal-better judgments
5. EN / ZH difference still breaks experiential equivalence

## EN / ZH exit rule
Literal wording parity is not required.
But before exit, EN and ZH must be similar in:
- weight
- invisibility
- non-explanation
- not stealing the layer

## Tree closure rule
Tree may move I toward closure-ready only if:
- self-blame is no longer single-path
- bracing / over-effort show initial transfer proof
- suppression stays stable
- Lumen reports no meaningful weight drift
- Nova did not buy coverage by increasing mechanism-feel
- OctopusMind boundaries remain intact
- Wisewave language remains felt-not-stated

## External-ready threshold
### Internal-stable
- multi-path proof exists
- no obvious drift
- suppression stays stable
- cue stays light

### External-ready
- at least 2 families work
- EN / ZH are not obviously weight-skewed
- no memory-feel red flag
- removal-better is no longer the dominant pattern

## One-line exit rule

**Milestone I may exit only when support widens while presence stays flat.**

## Final closure test

If I works in more places, but the user still barely feels that the system is continuing, then I is complete.

## Final truth

Milestone I should not close because one path works.
It should close only when a narrow-path miracle has become a stable but quiet system capability.
