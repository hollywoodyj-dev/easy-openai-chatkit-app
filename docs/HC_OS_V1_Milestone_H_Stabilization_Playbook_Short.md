# HC-OS V1 — Milestone H Stabilization Playbook (Short)

**Status:** Soft pass / stabilization  
**Audience:** Tree, Lumen, Nova, Wisewave  
**Purpose:** Keep Milestone H small, light, non-intrusive, and stable under real use.

---

## 1. Current phase

Milestone H is **not** in expansion mode.
It is **not** ready to open Milestone I.
It is in:

> **Milestone H — soft pass / stabilization**

Meaning:
- H is validated
- H is usable
- H is **not hard-closed**
- the current job is to preserve containment, not add scope

---

## 2. Core operating rule

> **Contain H. Don’t grow H.**

If a change makes H:
- more visible
- more frequent
- more system-like
- more “helpful” but heavier

…it is likely the wrong move.

---

## 3. What H must remain

H must stay:
- optional
- rare
- suppressible
- removable
- subordinate to reflection
- subordinate to Milestone E
- lighter than the instinct to keep it

---

## 4. Live QA decision rule

For any turn where H appears, ask:

1. Does H steer?
2. Does H explain the user?
3. Does H sound too certain / knowing?
4. Does H make the turn heavier?
5. Does H duplicate reflection or E?
6. If I remove H, is the response better, same, or only slightly worse?

### Action rule

If the answer to any of the above points toward excess:
- **remove / suppress H**

Only keep H if:
- removing it makes the turn **clearly worse**

---

## 5. Five drift axes

Use these labels when evaluating stabilization drift:

- **guidance drift** — H starts steering
- **interpretive drift** — H starts explaining
- **authority drift** — H sounds like it “knows”
- **weight drift** — H makes the turn denser / heavier
- **duplication drift** — H overlaps reflection or E

If any axis triggers:
- prefer suppression
- treat “almost helpful” as insufficient

---

## 6. Frequency rule

Healthy H means:

- **70–85% of turns should have no H**

Warning signs:
- H appears too often
- H appears consecutively
- H appears on low-signal inputs
- users can start noticing H as a recurring product behavior

> **If H becomes noticeable, it is already too much.**

---

## 7. Stack rule

Priority order:

- **E > H**
- **Reflection > H**
- **Overall lightness > H**

So:
- if recurrence is present, H should stay out
- if the turn already feels layered, H should stay out
- if H competes with clarity, H should stay out

---

## 8. Light Mode dependency

H only remains healthy if the main reflection stays light.

If the reflection layer drifts back toward:
- over-explaining
- over-resolving
- subtle guidance
- authorial certainty

then H becomes invalid again.

Protecting **Light Mode** is part of protecting **H**.

---

## 9. EN / ZH rule

Parity means:
- same restraint
- same optionality
- same admissibility fairness
- same suppression discipline

It does **not** mean literal wording match.

If ZH becomes:
- heavier
- more teacher-like
- or more heavily blocked by heuristics

that is stabilization drift.

---

## 10. Success condition

Milestone H success no longer means “many nice examples.”

It means:
- H rarely appears
- when it appears, it helps a little
- most turns do not need it
- the system feels lighter than before
- H is easy to forget

> **If you almost forget H exists, and that feels correct, stabilization is working.**

---

## One-line team version

> **Milestone H is now in containment mode: keep H rare, light, removable, and easy to suppress, and treat any drift toward guidance, weight, or visibility as a reason to pull it back.**
