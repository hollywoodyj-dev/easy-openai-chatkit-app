## Addendum to Milestone E

## E3 — User-Facing Continuity Legibility

### 0. Status of this addendum

This addendum extends Milestone E Final Definition after E2 acceptance.

E1 proved that an earned recurrence cue can function as a light continuity layer.

E2 proved that one repeated inner pattern can remain legible across a minimal recent-insight substrate without drifting into repetition, tracking, or history-product behavior.

E3 exists to define the next narrow step.

Its purpose is not to expand memory depth, add a history interface, or widen the product into an analytics layer.

Its purpose is to prove that:

one repeated inner pattern can become more clearly legible to the user without making the product heavier.

### 1. E3 execution intent

E3 must be executed as a continuity-legibility step, not as a memory-expansion step.

The aim is not:

- more stored history
- more cues
- more pattern inventory
- more UI components
- more analytical explanation

The aim is:

- to make one repeated inner pattern easier for the user to recognize as continuity while preserving lightness, restraint, and reflection-first product behavior.

### 2. What E3 must prove

E3 should prove three things:

#### 2.1 Continuity can become more user-legible

The user can more easily sense:

- this is not random
- this is not only a one-turn cue
- something familiar is remaining present

#### 2.2 Product shape stays light

Continuity becomes clearer without turning the experience into:

- a history viewer
- a journaling surface
- a tracking tool
- an analytics layer

#### 2.3 Reflection remains the center of gravity

The product must still feel:

- reflection-first
- continuity-supported
- non-authoritative
- non-monitoring

### 3. Governing product rule

E3 must not be interpreted as:

- more visible continuity = better continuity

That is false.

Better continuity in E3 means:

- clearer user legibility of one repeated pattern, with no major increase in surface weight.

If the system becomes more explicit but also more intrusive, E3 has failed.

### 4. Scope of E3

In scope

- refinement of user-facing continuity presentation
- small continuity-legibility improvements in wording, placement, or timing
- one clearer but still light pattern continuity expression
- founder-readable continuity demo improvement
- EN/ZH baseline compatibility

Out of scope

- history panel
- insight archive
- searchable memory
- tags / filters / categories
- charts / analytics
- awareness map
- multi-pattern summary view
- embodiment loop
- recommendation engine
- large UI expansion
- multilingual expansion beyond EN/ZH baseline

E3 is not a memory milestone.

It is a legibility milestone.

### 5. Legibility rule

E3 must improve the user’s ability to recognize continuity without increasing product heaviness.

This means continuity should feel:

- more readable
- more natural
- more coherent
- more obviously connected to current reflection

It must not feel:

- more intrusive
- more repetitive
- more diagnostic
- more like the product is building a user model

### 6. Lightness rule

Any E3 gain in legibility must preserve lightness.

Required rule

- If a continuity improvement makes the UI or experience feel noticeably heavier, it is not a valid E3 improvement.

Product meaning

- The user should feel:
  - "I can see this more clearly"
  - not:
  - "The system is now doing more to me"

### 7. Reflection-first rule

Reflection must remain the primary value layer.

Continuity in E3 should still function as:

- a support layer
- a structural cue
- a light continuity aid

Continuity must not become:

- the main event
- the dominant visual element
- a running pattern narration
- a replacement for reflection quality

### 8. Anti-expansion rule

E3 must not solve legibility by adding product mass.

Do not add:

- a visible history stack
- multiple simultaneous continuity layers
- persistent pattern dashboard behavior
- explanatory panels
- structured pattern summaries
- monitoring-like UI

E3 should solve legibility with:

- better phrasing
- better timing
- better visibility discipline
- better continuity-readability balance

### 9. User-visible continuity rule

E3 user-visible continuity should help the user feel:

- this pattern is still relevant
- this continuity belongs to the present moment
- this is one recognizable thread, not a system inventory
- the product is helping me notice, not defining me

The best E3 continuity experience should feel like:

- "I can see the thread more clearly now."

Not:

- "The system is showing me more data about myself."

### 10. EN / ZH parity rule

E3 improvements must preserve bilingual baseline compatibility.

English and Chinese do not need literal matching.

They must preserve:

- the same continuity function
- the same lightness
- the same confidence feel
- the same restraint
- the same readability

If one language becomes noticeably heavier, more certain, or more analytical, E3 is drifting.

### 11. Founder demo rule

E3 must improve founder-readable continuity legibility.

The founder demo should make it easier to see:

- one repeated pattern is present
- that pattern belongs to the current reflection
- continuity is clearer than in E2
- the product is still light
- the experience still reads as continuity layer, not tracking layer

If E3 requires too much explanation to justify its added value, it is not ready.

### 13. Acceptance gate

E3 should be marked complete only if all of the following are true:

- One repeated pattern is more clearly legible to the user than in E2.
- The product does not become heavier in feel.
- Reflection remains primary.
- Continuity still feels like support, not system authority.
- The product still reads as a continuity layer, not a history/tracking layer.
- EN/ZH baseline compatibility still holds.
- Scope remained narrow.

If these are not all true, E3 should not be treated as complete.

### 14. Final execution instruction

E3 must be built as the smallest valid user-legibility upgrade to Milestone E.

Its job is not to make the system bigger.

Its job is to make one repeated inner pattern easier for the user to recognize:

- lightly
- clearly
- without added heaviness
- without memory-product drift
- without authority drift
- without losing reflection-first structure

No more should be built than what is necessary to prove that.

present-moment sensitivity

a label

clearer, but not heavier

calm
light

connected

“I can see the thread more clearly.”

“The system is doing more interpretation on me.”

E3 wording refinement should improve clarity of continuity, not amount of language.
Good refinement does
sharpens the sense of “same thread”
reduces ambiguity where useful
improves present relevance
makes continuity feel natural beside the main reflection
Bad refinement does
adds more words instead of more clarity
sounds more advanced but feels less human
repeats continuity language mechanically
becomes more explanatory than necessary
Rule
If a wording change makes continuity more obvious but less light, reject it.
5. Anti-heaviness language boundary
This is one of the core boundaries of E3.
5.1 Required rule
No E3 continuity language should create a feeling of:
monitoring
profiling
accumulation
psychological pressure
“ongoing issue” framing
5.2 Heaviness warning signs
Continuity language is too heavy when it starts to feel like:
a running commentary
a pattern report
a mini-analysis
a system memory statement
a repeated assertion of the same truth
5.3 Safe zone
Safe continuity language should feel like:
a light thread marker
a present-moment continuity aid
a soft connection between now and what has been recurring
Core rule
E3 may improve legibility, but it may not increase interpretive weight.

}

3. Template selection utility
export function getE3Templates(
  templateMap: LegibilityTemplateMap,
  patternId: PatternId,
  state: LegibilityState,
  lang: DisplayLang
): string[] {
  if (patternId === "generic") {
    return templateMap.generic_templates[state][lang];
  }

  return (
    templateMap.pattern_templates[patternId]?.[state]?.[lang] ??
    templateMap.generic_templates[state][lang]
  );
}
4. Variant picker
目标不是“随机”，而是避免连续两次完全一样。
export function pickE3TemplateVariant(
  templates: string[],
  currentTurnIndex: number,
  lastRenderedAtTurn?: number | null
): { text: string; variant: number } {
  if (!templates.length) {
    return { text: "", variant: -1 };
  }

  const baseIndex = currentTurnIndex % templates.length;

  if (
    lastRenderedAtTurn != null &&
    currentTurnIndex - lastRenderedAtTurn <= 1 &&
    templates.length > 1
  ) {
    const nextIndex = (baseIndex + 1) % templates.length;
    return { text: templates[nextIndex], variant: nextIndex };
  }

  return { text: templates[baseIndex], variant: baseIndex };
}
5. Core selector pseudocode
E3 的核心原则：
clearer, not heavier
proof before retention-dependent rendering
main reflection stays primary
export function selectE3LegibilityCue(
  ctx: E3RenderContext,
  templateMap: LegibilityTemplateMap,
  thresholds: E3LegibilityThresholds = DEFAULT_E3_THRESHOLDS
): E3SelectorResult {
  // 1. Hard gates
  if (!ctx.continuityState) {
    return {
      shouldRender: false,
      reason: "no_continuity_state",
      cue: null
    };
  }

  if (!ctx.continuityState.isEligible) {
    return {
      shouldRender: false,
      reason: "not_eligible",
      cue: null
    };
  }

  if (!ctx.continuityState.proofThresholdPassed) {
    return {
      shouldRender: false,
      reason: "proof_not_passed",
      cue: null
    };
  }

  if (ctx.latestIsVagueSource) {
    return {
      shouldRender: false,
      reason: "vague_source",
      cue: null
    };
  }

  if (!ctx.latestMetadataExists || !ctx.latestMetadataMeaningful) {
    return {
      shouldRender: false,
      reason: "metadata_not_meaningful",
      cue: null
    };
  }

  // 2. Legibility value gates
  if (ctx.continuityState.presentRelevance < thresholds.minPresentRelevanceToRender) {
    return {
      shouldRender: false,
      reason: "low_present_relevance",
      cue: null
    };
  }

  if (ctx.continuityState.clarityGain < thresholds.minClarityGainToRender) {
    return {
      shouldRender: false,
      reason: "low_clarity_gain",
      cue: null
    };
  }

  // 3. Anti-heaviness / anti-authority gates
  if (ctx.continuityState.addedWeightRisk > thresholds.maxAddedWeightRisk) {
    return {
      shouldRender: false,
      reason: "added_weight_too_high",
      cue: null
    };
  }

  if (ctx.continuityState.authorityRisk > thresholds.maxAuthorityRisk) {
    return {
      shouldRender: false,
      reason: "authority_risk_too_high",
      cue: null
    };
  }

  // 4. Anti-repetition gates
  if (ctx.continuityState.repetitionRisk > thresholds.maxRepetitionRisk) {
    return {
      shouldRender: false,
      reason: "repetition_risk_too_high",
      cue: null
    };
  }

  if (
    (ctx.continuityState.consecutiveRenderCount ?? 0) > thresholds.maxConsecutiveRenderCount
  ) {
    return {
      shouldRender: false,
      reason: "repetition_risk_too_high",
      cue: null
    };
  }

  // 5. Reflection-first gate
  if (ctx.mainReflectionAlreadyCarriesContinuityClearly) {
    return {
      shouldRender: false,
      reason: "main_reflection_already_enough",
      cue: null
    };
  }

  // 6. Drift guard
  const driftTriggered =
    ctx.continuityState.clarityGain < ctx.continuityState.addedWeightRisk;

  if (driftTriggered) {
    return {
      shouldRender: false,
      reason: "drift_guard_triggered",
      cue: null
    };
  }

  // 7. Resolve templates
  const templatesEn = getE3Templates(
    templateMap,
    ctx.continuityState.patternId,
    ctx.continuityState.legibilityState,
    "en"
  );

  const templatesZh = getE3Templates(
    templateMap,
    ctx.continuityState.patternId,
    ctx.continuityState.legibilityState,
    "zh"
  );

  const pickedEn = pickE3TemplateVariant(
    templatesEn,
    ctx.currentTurnIndex,
    ctx.continuityState.lastRenderedAtTurn
  );

  const pickedZh = pickE3TemplateVariant(
    templatesZh,
    ctx.currentTurnIndex,
    ctx.continuityState.lastRenderedAtTurn
  );

  const cue: E3LegibilityCue = {
    patternId: ctx.continuityState.patternId,
    legibilityState: ctx.continuityState.legibilityState,
    textEn: pickedEn.text,
    textZh: pickedZh.text,
    selectedText: ctx.uiLang === "zh" ? pickedZh.text : pickedEn.text,
    templateVariant: ctx.uiLang === "zh" ? pickedZh.variant : pickedEn.variant
  };

  return {
    shouldRender: true,
    reason: "render",
    cue
  };
}
6. Legibility state resolver
E3 不只是 persistence 继续说，而是要判断：
现在 render 会不会真的让 continuity 更容易看见。
export interface E3LegibilityCandidate {
  patternId: PatternId;
  presentRelevance: number; // 0..1
  clarityGain: number; // 0..1
  addedWeightRisk: number; // 0..1
  authorityRisk: number; // 0..1
  proofThresholdPassed: boolean;
  isEligible: boolean;
}

export function resolveE3ContinuityState(
  candidate: E3LegibilityCandidate,
  previousState?: ContinuityState | null
): ContinuityState | null {
  if (!candidate.isEligible || !candidate.proofThresholdPassed) {
    return null;
  }

  // Light vs clear is based on clarity value, not just recurrence count
  const legibilityState: LegibilityState =
    candidate.clarityGain >= 0.72 ? "clear" : "light";

  return {
    patternId: candidate.patternId,
    isEligible: true,
    proofThresholdPassed: true,
    legibilityState,
    presentRelevance: candidate.presentRelevance,
    clarityGain: candidate.clarityGain,
    addedWeightRisk: candidate.addedWeightRisk,
    authorityRisk: candidate.authorityRisk,
    repetitionRisk: previousState?.patternId === candidate.patternId ? 0.3 : 0.1,
    lastRenderedAtTurn:
      previousState?.patternId === candidate.patternId
        ? previousState.lastRenderedAtTurn ?? null
        : null,
    consecutiveRenderCount:
      previousState?.patternId === candidate.patternId
        ? previousState.consecutiveRenderCount ?? 0
        : 0
  };
}
7. Render lifecycle update pseudocode
export function updateContinuityStateAfterRender(
  state: ContinuityState | null,
  currentTurnIndex: number,
  rendered: boolean
): ContinuityState | null {
  if (!state) return null;

  if (!rendered) {
    return {
      ...state,
      consecutiveRenderCount: 0
    };
  }

  return {
    ...state,
    lastRenderedAtTurn: currentTurnIndex,
    consecutiveRenderCount: (state.consecutiveRenderCount ?? 0) + 1
  };
}
8. Example usage flow
// 1. Build candidate from current proof-eligible continuity state
const candidate: E3LegibilityCandidate = buildE3Candidate(...);

// 2. Resolve continuity state
const continuityState = resolveE3ContinuityState(candidate, previousContinuityState);

// 3. Run selector
const result = selectE3LegibilityCue(
  {
    uiLang,
    currentTurnIndex,
    latestIsVagueSource,
    latestMetadataExists,
    latestMetadataMeaningful,
    mainReflectionAlreadyCarriesContinuityClearly,
    continuityState
  },
  e3TemplateMap
);

// 4. Render only if approved
if (result.shouldRender && result.cue) {
  renderContinuityCue(result.cue.selectedText);
}

// 5. Update lifecycle state
const nextState = updateContinuityStateAfterRender(
  continuityState,
  currentTurnIndex,
  result.shouldRender
);
9. What Nova should avoid
不要这样做
if (continuityState?.isEligible) {
  renderContinuityCue(...);
}
因为这会把 E3 变成：
只要 continuity 还在，就默认显示
这正是 E3 要避免的 memory-first drift。
也不要这样做
if (proofThresholdPassed) {
  useLongestOrMostExplicitTemplate();
}
因为 E3 不是“证明更强，就说更重”。
E3 的规则是：
clarity gain must exceed weight gain

11. Final implementation rule
E3 的正确感觉应该是：
The same thread becomes easier to see, without the product feeling more forceful.
而不是：
The system is surfacing more because it remembers more.
