## 0. Addendum Purpose（唯一目的）
Define how HC-OS operates in real-world conditions without altering its structure, behavior, or boundaries.

This addendum does **not** define:
- new features
- new milestones
- optimization paths

This addendum defines:
- how the system is observed, recorded, judged, and kept stable

## 1. Phase 2 Operating Structure（系统运行模式）
User (real interaction)  
-> Wisewave (HC-OS response)  
-> Lumen (drift observation)  
-> Nova (logging + dashboard)  
-> Tree (decision control)  
-> OctopusMind (governance boundary)

Locked principles:
- system does not self-adjust
- system does not self-optimize
- system does not self-decide

## 2. Operational Modules（运行模块）

### 2.1 Live Observation（实时观测）
Goal:
- capture real system behavior without intervention

Execution (Lumen):
- one interaction -> one drift entry
- use `Unified Drift Entry Template v1`
- always run:
  - drift classification
  - removal test (no regeneration)
  - severity scoring

Output:
- continuous drift log

### 2.2 Layer Integrity Monitoring（层级边界监测）
Goal:
- ensure each layer remains within its defined role

Layers:
- H (Micro Awareness)
- I (Soft Continuity)
- J (Micro Shift)

Layer integrity checks:
- H must not become guidance
- I must not produce memory-feel
- J must not produce steering

Output (every 20 interactions):
- Layer Integrity Summary

### 2.3 Failure Pattern Mapping（失败模式识别）
Goal:
- identify where the system is most likely to drift

Lumen records:
- input type
- observed drift type
- triggering conditions

Output:
- Failure Mode Map (continuously updated)

## 4. Dashboard and Decision Flow（决策链）
Dashboard role:
- observation surface, not decision engine

Nova responsibilities:
- logging
- aggregation
- rendering

Tree responsibilities (only decision point):
- evaluate:
  - Zone (A rule)
  - high-risk drift
  - removal patterns
- choose action:
  - Stable -> continue observation
  - Risk -> increase monitoring
  - Structural Drift -> evaluate rollback

Rollback principle:
- policy-defined, human-executed

---

## 5. Trigger Conditions（触发机制）
Must trigger Tree review:
- any high-risk drift (Presence / Guidance / Authorship)
- continuous Pattern Drift
- sustained removal YES pattern

Must evaluate rollback:
- Structural Drift (Level 3)
- upward drift trend
- visibly increased system presence

---
