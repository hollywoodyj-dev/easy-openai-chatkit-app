# Phase 6 Execution Memo
## Continue Mechanism — Selectivity, Trust, and Dependency Formation

### Audience
Tree / Nova / Lumen / Wisewave

### Status
Active

### Priority
High

### Phase purpose
Phase 6 is not about redefining Continue.

That work is already closed.

Phase 6 is about improving the conditions under which Continue becomes trusted enough to be reused, without making it heavier, more visible, or more system-like.

The central constraint from Phase 5 Batch 1 is now clear:

**Continue is more trustworthy when used than it is trustworthy about when to appear.**

So Phase 6 must focus on appearance discipline first.

---

## 0. One-line phase definition

**Phase 6 = make Continue more earned, more selective, and more reusable without expanding its product identity.**

---

## 1. Starting point

What is already true:

- Continue object definition is settled
- Phase 4 closure stands
- post-click resumed-turn quality is materially improved
- low-verbal re-entry can work
- healthy ignore path is intact
- early dependence formation is visible in strong cases

What is not yet true:

- Continue is not yet selective enough in low-value cases
- weak shallow/utilitarian returns can still surface Continue
- that over-appearance weakens trust and caps stronger reliance formation

Examples of low-value surfacing that should be treated as warning cases:
- “Hey”
- “Tomorrow at 9 works.”

These are not good trust-building moments for Continue.

---

## 2. Core Phase 6 objective

Improve **suppression discipline** and **surfacing precision** so that Continue appears more often in moments where it genuinely reduces restart cost, and less often in moments where it behaves like decorative UI.

The practical goal is:

**fewer weak appearances, preserved strong usefulness**

---

## 3. What success looks like

Phase 6 succeeds if all of the following become more true:

### A. Continue appears less in low-value cases
Users should stop seeing Continue in shallow, utilitarian, or clearly fresh-start returns.

### B. Strong-candidate usefulness remains intact
Continue must still perform well in:
- unfinished emotional residue
- interrupted articulation
- low-verbal re-entry
- recent live unfinished return

### C. Trust increases through selectivity
Users should increasingly learn:
- when Continue appears, it usually helps

### D. Ignore path remains healthy
Users must still be able to ignore Continue without penalty or awkwardness.

### E. No object drift occurs
Continue must not drift into:
- history
- memory exposure
- summaries
- topic browser
- larger visible system object

## 5. Nova execution focus

## Priority 1 — Suppression precision
This is the top priority.

Nova should aggressively improve non-surfacing in:
- shallow greetings
- utilitarian scheduling replies
- obvious fresh starts
- low-burden returns
- weak-candidate cases
- repetitive low-specificity residue cases

The operating bias should be:

**if uncertain, hide**

Not:
- if uncertain, show something

### Desired effect
The user should increasingly feel:
- “Continue appears when it has a reason”

Not:
- “Continue is usually there”

---

## Priority 2 — Surfacing precision
After suppression tightens, Nova should refine positive surfacing logic for strong moments.

Strong moments likely include:
- unfinished emotional carry
- unresolved internal tension
- interrupted articulation
- recent unfinished reflective direction
- low-verbal resumable return

The key is not just detecting unfinishedness.
It is detecting **restart-cost relevance**.

That should become the main surfacing principle.

---

## Priority 3 — Preserve strongest use path
While tightening surfacing, Nova must not damage the best working path:

- user returns in a strong unfinished direction
- Continue appears
- user selects
- user sends a short re-entry input
- first reply clearly resumes

This path is the strongest trust builder and must be protected.

---

## Priority 4 — Instrumentation
Nova should instrument Phase 6 around trust and selectivity, not only usage.

Minimum recommended measures:
- Continue impression rate
- Continue click rate in strong-candidate cases
- weak-case impression rate
- suppression rate in weak/no-value cases
- repeat-use rate after successful use
- time-to-next-message after click
- next-input length after click
- first post-click resumed-turn coherence
- ignore-path cleanliness

Important:
A lower impression rate may be a success if trust quality rises.

---

## 6. Lumen QA gates

Lumen should validate Phase 6 primarily through comparison:

### A. Has weak-case surfacing decreased?
Test specifically:
- greetings
- logistical replies
- shallow returns
- fresh-start returns
- low-burden returns

Question:
- is Continue now hidden more often where it should be?

### B. Are strong cases still intact?
Test specifically:
- unfinished emotional return
- interrupted articulation
- recent still-live unfinished return
- low-verbal continuation after selection

Question:
- does stronger suppression leave the best path untouched?

### C. Has selectivity become more trustworthy?
Question:
- when Continue appears now, does it feel more earned?

### D. Is ignore still healthy?
Question:
- can users still ignore it without friction?

### E. Did resumed-turn quality regress?
Question:
- after stronger suppression tuning, does post-click continuation still feel resumed rather than restarted?

---

## 7. Wisewave felt-experience criteria

Wisewave should evaluate Phase 6 against these standards:

### 1. Earned appearance
Continue should feel more deserved when visible.

### 2. Lower decorative feel
It should feel less like UI furniture.

### 3. Maintained gentleness
Tighter surfacing should not make the system feel cold, rigid, or over-withholding.

### 4. Trust through restraint
Selective absence can strengthen felt trust if strong appearances remain good.

### 5. Continued lightness
The mechanism must still feel like a soft continuity cue, not a visible continuity system.

---

## 8. Hard constraints

## Do not do
- do not reopen Thread vs Continue definition
- do not expand into history/memory/summaries
- do not add explanatory UI to improve adoption
- do not increase prominence to force usage
- do not optimize for raw click volume
- do not trade selectivity for constant visibility

## Stay focused on
- suppression quality
- surfacing quality
- trust formation
- restart-cost reduction
- low-friction repeatability
- boundary integrity

---

## 9. Pass / hold criteria

## Pass Phase 6 if:
- weak-case surfacing clearly decreases
- strong-case usefulness remains strong
- resumed-turn quality remains intact
- Continue feels more earned when present
- ignore path stays healthy
- no new drift into adjacent product objects appears

## Hold Phase 6 if:
- suppression improves only by harming strong useful cases
- resumed-turn quality weakens materially
- Continue still appears too often in low-value returns
- the team tries to compensate with more visibility or explanation
- object drift reappears

---

## 10. Main evaluation question

The main question for Phase 6 is not:

- “Is Continue good?”

It is:

**“Is Continue becoming more selective without losing the moments that make it worth relying on?”**

That is the release gate.

- less frequent when weak

Do not make it bigger.

Do not make it more conceptual.

**Make it more earned.**
