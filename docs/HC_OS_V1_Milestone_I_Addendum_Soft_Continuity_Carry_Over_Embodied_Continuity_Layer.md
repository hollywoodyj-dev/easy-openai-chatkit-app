# HC-OS V1 — Soft Continuity Carry-Over / Embodied Continuity Layer

Status: Formal execution addendum

Audience: Tree, OctopusMind, Nova, Lumen, Wisewave

0. Purpose of this addendum

This addendum exists to make Milestone I executable without allowing it to widen into memory product behavior, tracking behavior, or guidance behavior.

Milestone I is the next narrow step after Milestone H closure.

If:

- Milestone D proved meaningful reflection can work
- Milestone E proved repeating inner patterns can become visible
- Milestone H proved awareness can lightly enter a live moment without becoming intrusive

then Milestone I must prove:

- a light inner awareness can subtly carry forward across nearby moments without being re-imposed

This addendum defines:

- the correct milestone essence
- the proof target
- the execution boundary
- agent ownership
- implementation constraints
- suppression and decay rules
- QA and acceptance discipline
- anti-drift protections

1. Milestone I strategic definition

Milestone I should be treated as:

- a carry-over milestone, not a memory milestone

Milestone I is not allowed to create the feeling that the system is:

- tracking the user
- reminding the user
- replaying prior insight
- preserving too much continuity state
- building a visible identity model

Milestone I is only allowed to establish:

- soft continuity of inner space

That means the system may lightly preserve a felt thread across nearby turns, but may not:

- explicitly resurface old content as a product act
- state prior insight too directly
- repeat prior language
- convert continuity into a visible feature layer

2. Primary proof target

Milestone I passes only if the product can demonstrate the following:

- a meaningful reflective thread can remain faintly present across nearby moments without increasing system presence

The proof is not:

- stronger memory
- more continuity cues
- more visible recall
- more system persistence
- more explicit connection-making

The proof is:

- slightly less reset feeling
- slightly more inner continuity
- preserved lightness
- preserved trust
- preserved product restraint

3. Milestone I product rule

The correct product rule for I is:

- carry forward lightly, do not restate

Good I behavior:

- feels continuous without announcing continuity
- lightly reflects an already-open inner space
- preserves subtle coherence
- stays easy to suppress
- disappears easily when the thread weakens

Bad I behavior:

- recalls prior insight explicitly
- sounds like "as before"
- teaches continuity to the user
- preserves too much across turns
- turns the system into an active continuity agent

4. In-scope components

Milestone I is allowed to contain only the following minimal components:

I1. Soft continuity carry-over

- A faint carry-over of the same reflective atmosphere or inner thread into the next relevant moment.

I2. Near-turn coherence preservation

- A minimal mechanism that helps the system avoid sounding reset when the user remains in the same inner space.

I3. Light continuity shaping

- Very small wording influence from a recent reflective thread, without explicit restatement or surfacing.

I4. Decay-governed continuity

- Carry-over must weaken naturally and disappear quickly when not supported.

No additional components are authorized under this addendum.

5. Out-of-scope protections

The following are explicitly out of scope for Milestone I:

- memory expansion
- visible continuity UI
- insight replay
- explicit recall statements
- pattern dashboard behavior
- multi-turn continuity escalation
- identity-profile accumulation
- action recommendation continuity
- therapist-style treatment continuity
- habit reinforcement
- journaling behavior
- reminder behavior
- productized follow-through systems
- broader embodiment platform behavior
- multilingual expansion beyond English and Chinese baseline
- any new visible layer added to the response

If a proposed change requires any of the above, it is not Milestone I.

10. OctopusMind detailed addendum

10.1 OctopusMind mission for I

Protect Milestone I from becoming continuity-heavy, memory-like, or guidance-bearing.

10.2 Required OctopusMind outputs

OctopusMind must deliver:

- Admissibility rule
  - Carry-over is allowed only when the user remains in a clearly related inner thread and continuity can remain faint.
- Suppression rule
  - Carry-over must be suppressed when:
    - the turn is factual or utilitarian
    - the thread has weakened
    - continuity would need explicit recall to work
    - H is already doing the necessary work
    - E pattern surfacing is already active and sufficient
    - the output would become more noticeable than helpful
    - uncertainty is significant
- Decay rule
  - Carry-over must weaken quickly and disappear by default unless clearly re-earned.
- Conflict rule
  - If I overlaps with E or H, suppress I first.
- Uncertainty rule
  - If uncertain, suppress.
- Persistence rule
  - No long carry-over window. No cumulative strengthening without clear re-support from the current turn.

10.3 OctopusMind acceptance bar

OctopusMind work is complete only when Tree can use it to say:

- exactly when I may appear
- exactly when I must not appear
- exactly how it decays
- exactly why it remains subordinate to E and H
