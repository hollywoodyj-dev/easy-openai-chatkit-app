# Phase 6 Task — Adoption Tuning Without Identity Drift

## Subject
Phase 6 — Continue Adoption Tuning

## Audience
Tree / Nova / Wisewave

## Status
Active

## Priority
High

## Phase Goal
Turn Continue from an accepted mechanism into a quietly dependable user capability, without allowing it to drift into a larger visible product object.

---

## 0. One-line phase definition

Phase 6 is about increasing real user reliance on Continue
without increasing conceptual weight, UI heaviness, or product-object drift.

---

## 1. Strategic context

Phase 4 solved object definition.
Phase 5 clarified the experience path and identified the conditions under which Continue creates real value.

We now know:
- Continue works best when restart cost is real
- Continue should appear selectively, not constantly
- strong post-click resumed-turn quality is the main trust builder
- low-quality surfacing weakens confidence
- high-quality suppression is part of product success, not absence of product

This means the next phase is no longer about redefining the mechanism.
It is about tuning:
- when it appears
- when it hides
- when users trust it
- when they use it again
- what makes it quietly dependable

---

## 2. Core strategic question

How do we increase Continue adoption in high-value moments
without making Continue more visible, more explanatory, or more object-like?

---

## 3. Phase 6 objective

Improve Continue along four dimensions:

### A. Surfacing precision
Show Continue more accurately in the moments where it truly reduces restart cost.

### B. Post-click trust quality
Increase the reliability of the first resumed turn after selection.

### C. Repeat-use formation
Increase the likelihood that one successful Continue use leads to future reuse.

### D. Drift prevention
Ensure all tuning preserves Continue as a lightweight continuation affordance.

---

## 4. What this phase is not

Phase 6 is not for:
- reopening naming debates
- redefining Continue
- adding more explanation
- making the feature more prominent for its own sake
- turning Continue into history, memory, summary, or topic UI
- expanding its claims into a broad continuity architecture

Continue should become more useful, not more visible.

## 6. Workstreams

### Workstream A — Surfacing precision

#### Goal
Improve the quality of when Continue appears.

#### Focus
- high-confidence unfinished directions
- suppression in weak cases
- protecting against decorative presence
- reducing low-value impressions

#### Required questions
- Are we surfacing Continue only in moments of real restart burden?
- Are weak candidates being suppressed aggressively enough?
- Are multiple similar candidates being collapsed or hidden?
- Are fresh-start moments being left clean?

#### Success condition
Continue appears less like furniture and more like timely help.

### Workstream B — Return-pattern segmentation

#### Goal
Understand which return types benefit most from Continue.

#### Priority return patterns
- short pause return
- medium pause return
- emotional interruption return
- interrupted articulation return
- unresolved reflection return
- fresh-start return

#### Required questions
- Which return patterns generate the strongest uptake?
- Which patterns produce the best resumed-turn coherence?
- Which patterns should suppress Continue by default?
- Where does Continue create the highest effort savings?

#### Success condition
The team can identify where Continue is strongest, not just where it exists.

### Workstream C — Post-click resumed-turn quality

#### Goal
Strengthen the most important proof point:
the first reply after Continue selection.

#### Focus
- very short follow-up inputs
- low-verbal acknowledgments
- ambiguous re-entry language
- maintaining selected-direction coherence without over-anchoring

#### Required questions
- Does the first reply clearly feel resumed?
- Does minimal user language still work reliably?
- Does the system avoid collapsing into genericity?
- Does the assistant avoid acting like it needs the user to restart context?

#### Success condition
Users feel “it picked that up” quickly and consistently.

### Workstream D — Repeat-use formation

#### Goal
Increase the chance that one successful use leads to later reuse.

#### Focus
- trust-building conditions
- selective but valuable impressions
- low-friction re-entry
- relationship between first success and later adoption

#### Required questions
- After one successful Continue use, do users come back to it?
- Does Continue reduce manual restatement enough to be remembered?
- Does selective presence improve trust over time?
- What conditions convert “use once” into “use again”?

#### Success condition
Continue starts behaving like a dependency cue, not a novelty.

### Workstream E — Drift protection

#### Goal
Prevent adoption tuning from mutating the product object.

#### Drift risks to monitor
- history drift
- memory drift
- summary drift
- topic-browser drift
- explanation drift
- visibility inflation
- over-claim drift

#### Required rule
Any tuning that improves interaction metrics by increasing conceptual weight should be treated as suspect.

#### Success condition
Continue becomes more relied on while remaining lightweight and narrow.

## 7. Product signals to track

The following signals should be used together.

### A. Strong-candidate impression-to-click quality
Measure:
when Continue appears in strong cases, how often is it used?

Interpretation:
healthy selective usage is better than broad shallow usage

### B. Repeat usage rate
Measure:
after one successful Continue use, how often is it used again later?

Why it matters:
this is the clearest early adoption signal

### C. Time-to-next-message after click
Measure:
does Continue shorten hesitation before the next user input?

Why it matters:
lower hesitation suggests lower restart burden

### D. Next-input length after click
Measure:
are users able to continue with shorter messages?

Why it matters:
shorter follow-up often indicates real continuity support

### E. Repeated context restatement reduction
Measure:
after Continue selection, do users manually restate less prior context?

Why it matters:
this is one of the strongest markers of value

### F. First post-click response coherence
Measure:
how often does the first assistant reply align with the selected direction?

Why it matters:
this is the main trust conversion point

### G. Healthy ignore pattern
Measure:
when Continue is shown but not used, does the conversation still proceed cleanly?

Why it matters:
a healthy mechanism must allow non-use without penalty

### H. Suppression quality
Measure:
how often does the system correctly show fewer or zero options in weak cases?

Why it matters:
selectivity protects trust

## 8. Hard constraints

### Do not do
- do not increase visual prominence just to chase usage
- do not add explanatory copy to drive adoption
- do not surface weak candidates to keep the area populated
- do not turn options into topic names or mini-summaries
- do not optimize for CTR at the expense of trust
- do not widen Continue into a generalized memory or history system

### Preserve
- low friction
- low visibility
- user-action framing
- selective presence
- resumed-direction coherence
- easy ignore path

Phase 6 is successful if all of the following become clearer or measurably stronger:

### 1. Better surfacing judgment
Continue appears more often in high-value moments and less in weak ones.

### 2. Stronger first-turn proof
The first assistant response after selection more reliably feels like true continuation.

### 3. Healthier repeat use
Users who successfully use Continue are more likely to use it again.

### 4. Lower restart burden
Users restate less and re-enter faster.

### 5. No identity drift
The feature remains lightweight, non-technical, and non-object-like.

## Addendum — Phase 6 Implementation Clarifiers

These clarifiers are now treated as formal execution guidance for Phase 6.

### 1. Repeat-use must be evaluated under similar return conditions
Repeat-use should not be interpreted only through aggregate later reuse.

The more accurate question is:

**After one successful Continue use, does later reuse increase under similar high-value return conditions?**

Why this matters:
- aggregate reuse can be distorted by general activity changes
- similar-condition reuse is a better signal of learned trust
- it better captures whether Continue is becoming behaviorally dependable in the moments it was designed for

#### Required implication
Nova and later analysis should segment repeat-use by return pattern, especially:
- short pause return
- emotional interruption return
- interrupted articulation return
- unresolved reflection return

Repeat-use should be treated as strongest when it rises inside comparable high-value restart-cost moments.

### 2. Zero-surfacing is success in weak cases
In weak, low-confidence, or low-distinctness cases:
zero-surfacing is a successful outcome, not a missed opportunity.

Why this matters:
- showing nothing protects trust
- forcing visibility in weak cases makes Continue feel decorative or fake
- high-quality suppression is part of product quality

#### Required implication
Nova should not treat empty-state appearance as a product failure when:
- no meaningful unfinished direction exists
- candidate distinctiveness is too low
- previous interaction depth is too shallow
- user behavior clearly indicates a fresh start

#### Hard rule
Do not compensate for weak candidates by:
- fabricating softer filler options
- lowering quality thresholds to keep the surface populated
- increasing explanatory weight to justify presence

The correct outcome in weak cases is often:
- fewer options
- or no Continue surface at all
