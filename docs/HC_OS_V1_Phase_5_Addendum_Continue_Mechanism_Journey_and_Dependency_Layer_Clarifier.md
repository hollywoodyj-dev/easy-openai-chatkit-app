# HC-OS V1 — Phase 5 Addendum
## Continue Mechanism — Journey & Dependency Layer Clarifier

## 🧭 0. Purpose

This addendum exists to prevent Phase 5 from drifting into:
- feature expansion
- UI optimization loops
- copy refinement cycles

and to ensure Phase 5 stays focused on its only goal:

**Turn Continue into a relied-on behavioral layer**

---

## ⚠️ 1. Critical Shift Reminder

Phase 4 solved:

**What Continue is**

Phase 5 must **NOT** reopen that question.

Phase 5 must only answer:

**When and why users actually rely on Continue**

---

## 🧠 2. Core Misalignment to Avoid

The most likely failure mode in Phase 5:

**Trying to improve Continue instead of observing how it is used**

### Clarification

Phase 5 is **NOT** about:
- better labels
- better wording
- more visibility
- more explanation

Phase 5 **IS** about:
- where Continue reduces restart cost enough to be used again

---

## 🎯 3. Redefined Success Standard

Phase 5 success is **NOT**:
- higher click rate
- more exposure
- better comprehension

Phase 5 success **IS**:
- users naturally continue without restating context

### Observable outcome
- fewer “as I said earlier…”
- fewer context rebuilds
- shorter re-entry messages
- smoother follow-up turns

---

## 🧩 4. Continue Value Model (Locked)

Continue only has value if it reduces:

**Restart Cost**

Restart cost includes:
- recalling prior context
- reorganizing thoughts
- rebuilding emotional state
- re-explaining situation

### Addendum rule

If Continue does not reduce restart cost,
it has no product value

---

## ⚠️ 5. Appearance Discipline (Hard Constraint)

Continue must not become:
- always visible
- expected UI element
- attention-seeking component

### Rule

Continue appears only when it meaningfully reduces restart cost

If uncertain:

**Do not show Continue**

---

## 🧠 6. Trust Formation Loop

User reliance forms only if:

**(Accuracy × Consistency × Relevance) > Threshold**

### Addendum requirement

Phase 5 must explicitly observe:
- when Continue is trusted
- when it is ignored
- when it is abandoned

### Critical insight

Trust is lost faster than it is built

---

## ❗ 7. Failure Sensitivity (Must Monitor)

Continue is highly sensitive to:

### A. Wrong direction selection
→ immediate trust drop

### B. Repetitive / indistinguishable options
→ selection collapse

### C. No perceived effect after click
→ feature invalidation

### D. Appearing at irrelevant moments
→ attention rejection

### Rule

One bad experience weighs more than multiple good ones

---

## 🧭 8. Ignore Path is Healthy

Phase 5 must explicitly accept:

**Continue is not meant to be used every time**

### Healthy behavior
- user ignores Continue when not needed
- user uses Continue when restart cost is high

### Anti-pattern

Optimizing for universal usage

---

## 🧠 9. Continue is NOT a Feature

Reinforce:

**Continue is a behavioral affordance, not a feature**

### Implication

Do **NOT**:
- promote it
- explain it
- make it central UI object
- force interaction

It should feel like:

**A natural way to continue, not a system tool**

---

## 🧩 10. Measurement Clarification

Phase 5 measurement must prioritize:

### Primary signals
- reduction in context restatement
- time-to-next-meaningful-input
- resumed-turn coherence

### Secondary signals
- repeat usage
- click-through

### Anti-metric

Do not optimize for clicks alone

---

## 🔒 11. Boundary Protection

Continue must **NOT** drift into:
- history
- transcript recall
- memory explanation
- topic classification
- system-visible state modeling

### Rule

If Continue becomes explainable,
it is already drifting

---

## 🧭 12. Phase 5 Focus Question (Locked)

All Phase 5 work must answer:

**When does Continue become easier than restarting?**

Not:
- how to improve Continue
- how to describe Continue
- how to make Continue clearer

---

## 🌿 13. Final Instruction

Do not strengthen Continue’s presence.

**Strengthen its usefulness.**

---

---

## 🔚 最后一行总结

**Phase 5 is not about making Continue better.**  
**It is about making Continue used.**
